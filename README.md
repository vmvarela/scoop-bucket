# scoop-bucket

Scoop bucket for [vmvarela](https://github.com/vmvarela) tools.

## Usage

```powershell
scoop bucket add vmvarela https://github.com/vmvarela/scoop-bucket
scoop install sql-pipe
```

## Packages

| Package | Description |
|---------|-------------|
| [sql-pipe](https://github.com/vmvarela/sql-pipe) | Read CSV from stdin, query with SQL, write CSV to stdout |
| [damas](https://github.com/vmvarela/damas) | Draughts engine and apps (English draughts and Spanish damas) |

## How the manifests are built

The manifests are generated by the shared publisher in
[package-distribution](https://github.com/vmvarela/package-distribution)
(`scripts/scoop-publish.mjs`), pinned to a commit. `state/` holds the version and
hash per package and Windows architecture, so a release that ships only some
architectures keeps the previous ones instead of pointing at a missing file.

`.github/workflows/update.yml` runs on `repository_dispatch`
(`update-sql-pipe`, `update-damas`) or manually with a package and version. It
resolves the target from the catalog, regenerates `bucket/<package>.json` from
the release checksums, and commits the manifest with the candidate state.
